# 唐山像素智能｜竞品项目情报工作台

只收录 XRT 矿石智能分选设备和煤炭智能干选设备的**招标、候选人和中标**公开情报；不录入产品宣传、展会或泛技术文章。

## 公网发布

推送到 `main` 后，GitHub Pages 工作流自动构建并发布工作台。首次启用时，在仓库 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**。公开地址为：

`https://white1star.github.io/Xiangsu/`

## 每周自动更新

`每周竞品情报更新` 在每周一 09:10（Asia/Shanghai）执行，也可在 Actions 页面手动点击 **Run workflow**。

采集规则定义在 `config/scan-rules.json`（真实采集规则：入口、检索接口、栏目、关键词、分页上限、适配器类型），执行 `scripts/weekly-run.mjs`：

- `npm run update:intelligence` —— 每周增量（近 14 天窗口）
- `npm run backfill:intelligence` —— 2026 年历史补抓（2026-01-01 起）

适配器：
- `ggzy-api`：全国公共资源交易平台官方检索接口（聚合各省级平台），关键词×时间窗×分页扫描，命中后回取官方全文提取金额与中标人；
- `html-list`：官方栏目静态分页（中国煤科、甘肃经济信息网）；
- `home-scan`：栏目深页需 JS 渲染的平台只做入口页浅扫并如实标注覆盖限制（国能e招、中煤）；聚合站（中国煤炭招标网）产出的线索只进 `src/data/pending-review.json` 待复核队列，不入高置信台账；
- `probe`：被反爬拦截的站点（中国政府采购网）每次探测并如实记录失败原因，不绕过。

产物：`public/data/latest-run.json`（本次覆盖报告：每平台状态/页数/发现/入账/拒绝及原因）、`public/data/scan-state.json`（每平台最近扫描时间与结果）。只有全部 `required: true` 的规则成功扫描，才允许更新 `src/data/intelligence.json` 并自动提交。

## 防漏抓规则

- 每个必查公开平台都必须有成功检查记录；少一个即失败，不发布“已更新”。
- 新记录必须有标题、原始链接、来源、发布日期、招投标状态和官方原文证据；缺任何一项只进失败报告，不进台账。
- 金额与中标人只在结果类公告（中标结果/候选人/成交）原文中提取；招标阶段的控制价、保证金一律不当成交金额；无披露即“未披露”。
- 已存在的原始链接与同标题同日期公告不会重复写入。
- 聚合来源线索只能进待复核队列（置信度“中”），反查到官方原文后才可入高置信台账。
- 每次报告记录检查时间、扫描页数、发现数量、新增数量、拒绝数量及原因、失败来源。

## 需要登录的平台

`config/public-sources.json` 中 `access: registered` 的平台不会被绕过。后续获得公司账号后，可另建授权采集流程。
